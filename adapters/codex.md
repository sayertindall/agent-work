# Codex

At installation, inspect the active global `AGENTS.md`, project instructions, discovered skills, and enabled plugins. The audited local setup discovers both `~/.agents/skills` and `~/.codex/skills` plus plugin skills. Do not expose this collection in both roots. System and app capabilities are separate from the legacy workflow collection.

Invoke the named skill through the native skill mechanism or read its canonical `SKILL.md` when using an explicit file pointer. Use the current filesystem and shell tools for repository work. Tool names can vary between desktop, CLI, and releases; follow the live schema.

For authorized delegation use the current native subagent tool and available roles. Give writers isolated worktrees/clones and bounded permissions. Follow explicit session restrictions on delegation and model overrides. Do not create a user-owned task just to implement a subtask when the host distinguishes those operations.

Use available browser or native-app tools for the actual consumption surface. Use a real scheduler only when recurring work is authorized; save the objective and stopping condition. An ordinary final message does not schedule continuation.

Keep current model settings outside this repository. Do not import model IDs or obsolete tool aliases from pstack. A native goal is distinct from a durable plan; create one only when requested or required by the host.

Activation acceptance: inspect the skill catalog in a fresh session, confirm one canonical entry per name and resolvable references, reconcile global policy and legacy pstack hooks, then exercise the shared cases. This repository's structural validation alone is not live-host acceptance.
