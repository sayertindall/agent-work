# Interface

Identify the user's task, target surface, existing design system, and requested fidelity. Preserve project primitives and conventions. For a standalone artifact, choose the simplest form that supports its review question. Do not create a parallel design system for a small change.

Read [design and implementation](references/design.md) when creating or changing a UI. Read [interface review](references/review.md) when assessing one. Use the installed browser, native UI, or terminal capability appropriate to the surface; tool syntax does not belong in this skill.

Respect whether the request is a proposal, review, prototype, or implementation. Interactive iteration pauses for feedback only when that workflow was requested or a consequential product choice is unresolved. An authorized implementation continues through relevant checks and actual use of the changed flow. Report observed results separately from source-only assessment.
