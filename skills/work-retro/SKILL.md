# Learn from completed work

Read the requested completed and discarded plans, related evidence, and relevant corrections. Inspect transcripts only within the authorized scope. Identify repeated outcomes: unnecessary pauses, missed acceptance, wrong scope, redundant context, or delayed handoffs.

Before choosing a durable correction, read [improve from evidence](../steady/references/delivery-principles.md#improve-from-evidence).

For each useful finding, provide concrete examples, a likely mechanism, and the smallest proposed correction. Consider deleting or narrowing instructions before adding them. Prefer a code invariant or validator when it can prevent the actual failure. Keep project-specific learning in its project.

Describe the expected improvement and a realistic case that would test it. Separate recurring evidence from a one-off preference. Do not change skills, global policy, model configuration, or memories unless requested. Return proposals in the conversation unless a saved report was authorized.
