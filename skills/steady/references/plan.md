# Plan

Clarify the outcome, scope, constraints, and acceptance criteria. Inspect relevant implementation or prior decisions before proposing a design. Use [architecture](../../architecture/SKILL.md) for consequential boundary decisions and [interface](../../interface/SKILL.md) for user-flow decisions.

Resolve observable facts through authorized inspection. Ask only for missing decisions that materially change the result. A proposal remains a proposal; do not implement it or create durable files unless requested.

When a durable plan is wanted, use [work-plan](../../work-plan/SKILL.md). Completion is a decision-ready design with relevant tradeoffs, remaining questions, and a verifiable delivery path. It does not require inventing every function signature.
